# BookStack.Sdk

Типизированный клиент [BookStack](https://www.bookstackapp.com/) REST API для .NET 10.

Проверен на BookStack 26.05.3. Поведение, описанное ниже, получено вызовами к живой установке.

## Установка

Пакета в NuGet нет. Подключается исходниками: скопируйте `src/BookStackSdk` к себе либо добавьте
ссылку на проект.

```xml
<ProjectReference Include="path/to/BookStackSdk/BookStackSdk.csproj" />
```

## Быстрый старт

```csharp
services.AddBookStack(o =>
{
    o.BaseUrl     = "https://docs.example.com";
    o.TokenId     = Environment.GetEnvironmentVariable("BOOKSTACK_TOKEN_ID")!;
    o.TokenSecret = Environment.GetEnvironmentVariable("BOOKSTACK_TOKEN_SECRET")!;
});
```

Идентификатор и секрет держатся отдельными полями намеренно. Склеенные заранее в одну строку, они
однажды окажутся переставлены местами, а сервер на это отвечает тем же самым 401, что и на чужой
токен: по ответу вы не поймёте, что перепутали половинки.

```csharp
public sealed class Publisher(IBookStackContentApi content)
{
    public async Task<int?> PublishAsync(int bookId, string title, string markdown, CancellationToken ct)
    {
        var page = await content.CreatePageAsync(new BookStackPageCreate
        {
            BookId   = bookId,
            Name     = title,
            Markdown = markdown,
            Tags     = [new BookStackTag { Name = "source", Value = "pipeline" }],
        }, ct);

        return page?.Id;
    }
}
```

## Что внутри

| Интерфейс | Что покрывает |
|---|---|
| `IBookStackContentApi` | полки, книги, главы, страницы: CRUD из markdown, теги, листание |
| `IBookStackUploadsApi` | картинки галереи, вложения, обложки книг и полок |
| `IBookStackSearchApi` | поиск с построителем запроса и разбором смешанной выдачи |
| `IBookStackUsersApi`, `IBookStackRolesApi` | пользователи и роли |
| `IBookStackRecycleBinApi` | корзина: чтение, восстановление, окончательное удаление |
| `IBookStackSystemApi` | версия, базовый адрес, идентификатор установки |
| `IBookStackExportApi` | выгрузка в markdown, html, текст, pdf, архив |
| `IBookStackImportApi` | импорт архива ZIP: загрузка и запуск, перенос содержимого между установками |

## Что стоит знать до первого вызова

**Кириллица требует явной кодировки.** Тело обязано уходить UTF-8 с указанием кодировки в
`Content-Type`. Без этого поле приезжает пустым, и сервер отвечает не ошибкой разбора, а
«поле обязательно»: по ответу порчу байтов не отличить от собственной опечатки. В SDK это закрыто и
проверяется тестом по сырым байтам на проводе, а не по строке, потому что строка проходит и при
испорченной кодировке.

**Обложки ставятся не тем методом, каким кажется.** Обложка книги и полки отправляется методом
`POST` с полем подмены метода, а не честным `PUT` с multipart.

Причина в версии PHP. Начиная с 8.4 многочастное тело при `PUT` разбирает `request_parse_body()`, и
честный `PUT` работает. На PHP старше разбирается только `application/x-www-form-urlencoded`, а
файлы берутся из `$_FILES`, который заполняется лишь для `POST`: файл пропадает молча, при ответе
200. Подмена метода работает на любой версии, поэтому выбрана она.

**Удаление мягкое.** Объект уезжает в корзину и остаётся там, а его короткое имя (`slug`) остаётся
занятым. Удаление это две операции, и без второй повторное создание с тем же именем поведёт себя
иначе, чем первое.

**Список пользователей не отдаёт роли.** Их приходится дотягивать по каждому пользователю отдельно.
Это разница между «списком» и «обходом», и знать о ней лучше заранее.

**Ошибки приходят в своём конверте** `{"error":{"message":…,"code":…}}`, причём `code` дублирует
HTTP-статус. Справочника кодов, в отличие от некоторых API, заводить не из чего: различения в
ответе нет.

**Идентификатор установки годится как замок.** `GET /api/system` отдаёт `instance_id`, уникальный
на установку. По нему пишущий код может убедиться, что работает не на боевом портале: между стендом
и продом разница обычно ровно в одной строке адреса.

**Импорт это два вызова и всегда создание.** Загрузка архива (`POST /api/imports`) содержимое не
создаёт, его создаёт отдельный запуск. Между вызовами есть состояние, переживающее сбой: упавший
процесс оставляет висящий импорт, и убрать его можно только удалением. Обновления существующей
книги по совпадению имени или слага у импорта нет: повторный импорт даёт вторую книгу рядом с
первой. Полки не импортируются, потому что не выгружаются.

**Ограничение частоты объявляется заголовками.** На 429 приходит `Retry-After`, а `X-RateLimit-*`
идут на каждом ответе. Обработчик повторов уважает их в этом порядке.

## Токены для инструментов

Оба инструмента берут токены из переменных окружения. Писать их в постоянное окружение
пользователя не нужно — есть хранилище рядом со скриптами:

```powershell
./set-tokens.ps1          # спросит половинки токенов и зашифрует
./set-tokens.ps1 -Show    # что уже лежит (имена, без значений)
```

`tokens.secret.xml` шифруется средствами Windows (DPAPI) на связку «эта учётная запись + эта
машина»: файл, унесённый на другую машину, не расшифруется. Скрипты кладут значения в окружение
только на время запуска — ни в реестр, ни в постоянное окружение ничего не попадает.

Переносимый вариант — `tokens.env` по образцу `tokens.env.example`, простой текст `ИМЯ=значение`.
Оба имени внесены в `.gitignore`. Любой из файлов можно указать явно ключом `-TokenFile`.
Переменная, заданная руками в окне, имеет приоритет над файлом.

## Инструмент: перенос полки

`tools/BookStackShelfSync` — консольный перенос полки между установками, собран поверх этого SDK
(выгрузка книг архивами, импорт на приёмнике, сборка полки заново).

Проще всего звать обёрткой `./sync-shelf.ps1`; напрямую:

```powershell
$env:BOOKSTACK_FROM_TOKEN_ID = "…"; $env:BOOKSTACK_FROM_TOKEN_SECRET = "…"
$env:BOOKSTACK_TO_TOKEN_ID   = "…"; $env:BOOKSTACK_TO_TOKEN_SECRET   = "…"

dotnet run --project tools/BookStackShelfSync -- `
  --from https://help.altway.pro --to https://test.help.altway.pro `
  --shelf kitaiskie-ploshhadki-i-servisy --dry-run
```

Полный список ключей — `--help`. Что стоит знать до запуска:

- **`--dry-run` сначала.** Он показывает, что найдено на источнике и что уже лежит на приёмнике,
  и ничего не меняет.
- **Без `--replace` будут дубли**, потому что импорт всегда создаёт новое. С `--replace` прежняя
  книга удаляется и добивается из корзины. Добивание не про слаг (его удалённая книга не держит,
  новая получит то же короткое имя), а про то, чтобы не осталась запись, восстановление которой
  даст две книги с одним слагом.
- **Замок от переливания прода в прод** стоит до первой правки: сверяются `instance_id` обеих
  установок, и совпадение останавливает перенос (снимается `--allow-same-instance`).
- **Порядок при `--replace`** такой: прежняя книга уезжает в корзину ДО импорта (чтобы на приёмнике
  не оказалось двух сразу), а добивается ПОСЛЕ (чтобы упавший импорт не оставил приёмник вовсе без
  книги: из корзины она возвращается).
- **Права.** Токену приёмника нужно право на импорт содержимого. Корзина для `--replace` требует
  сразу двух прав — на управление настройками и на управление правами; без них перенос не падает,
  запись просто остаётся в корзине, и инструмент об этом говорит.
- **Ссылки на источник** ищутся в перенесённых страницах всегда, а правятся только по
  `--rewrite-links` и только в страницах на markdown: обновление страницы в SDK идёт markdown-ом, и
  подсовывать в это поле HTML визуального редактора значило бы превратить разметку в текст. Такие
  страницы инструмент перечисляет отдельно.
- **Права и роли не переносятся** ни в каком виде: архив несёт содержимое и картинки, а не доступы.

## Инструмент: выкладка документов из репозитория

`tools/BookStackDocsPush` — односторонняя выкладка дерева markdown-файлов на портал: каталог
становится книгой, подкаталог первого уровня — главой, файл — страницей.

Проще всего звать обёрткой `./push-docs.ps1` (четыре каталога, полка и стенд уже прошиты
умолчаниями; на боевой портал она не пустит без `-AllowProduction`). Напрямую:

```powershell
$env:BOOKSTACK_TOKEN_ID = "…"; $env:BOOKSTACK_TOKEN_SECRET = "…"

dotnet run --project tools/BookStackDocsPush -- `
  --to https://test.help.altway.pro --docs F:\AltWay\AltWayDocs `
  --book "Архитектура=Архитектура" --book "Будущее=Будущее" `
  --book "Инструкции/Единый-вход=Единый вход" --book "Инструкции/Клиент-WPF=Клиент-WPF" `
  --shelf "Документация проекта" --dry-run
```

Что стоит знать до запуска:

- **Файлы на диске не меняются.** Хранилище только читается, вся правка идёт на портал.
- **`--dry-run` не ходит на портал вовсе** — ни токена, ни сети. Он читает диск и печатает
  раскладку по книгам и главам, а заодно считает, сколько ссылок удастся переписать.
- **Повторный прогон идемпотентен.** Страница узнаётся по тегу `docs-path` с путём файла, поэтому
  переименование заголовка не плодит дублей, а неизменившийся текст не переписывается: лишние
  ревизии на портале это не бесплатно.
- **Переехавший файл забирает свою страницу.** Если файл сменил каталог или номер в имени
  (`03-Расчёты.md` → `04-Расчёты.md`), страница узнаётся по имени файла без номера и переезжает
  вместе с ним. Иначе каждый такой файл заводил бы вторую страницу, а с `--prune` первую бы ещё и
  снесло — уже после того, как дубль забрал адрес. Кандидат берётся только если он единственный.
- **Пустой файл пропускается**, а его прежняя страница НЕ считается осиротевшей: опустевший файл не
  повод сносить написанное. Портал пустую страницу всё равно не принимает.
- **Книге с правилом сортировки порядок не навязывается**: там его считает портал, и спор с ним
  означал бы переписывание книги каждый прогон.
- **Проходов два, и порядок обязателен.** Сначала все страницы встают на места (адрес известен
  только после создания: короткое имя раздаёт сервер), потом пишется содержимое с переписанными
  ссылками. Иначе ссылки указывали бы на ещё не существующие или уже изменившиеся адреса.
- **Переписывается только сопоставленное.** Ссылка на файл вне переносимых каталогов или на
  несуществующий путь остаётся нетронутой и попадает в отчёт: битая ссылка видна, а подменённая
  «похожей» притворяется рабочей.
- **Якоря отбрасываются**: заголовкам BookStack раздаёт свои идентификаторы (`bkmrk-…`), перенести
  наш якорь в них нечем.
- **Каталоги и файлы с точки в начале пропускаются** (`.claude`, `.git`) — там оснастка, а не
  документация.
- **Страницы, чей файл исчез**, только перечисляются. Снести их — ключ `--prune`: удаление файла в
  репозитории и удаление страницы на портале это разные решения.
- **Замок `--expect-instance <id>`** не даёт вылить сотни страниц не на тот портал.

## Чем это не является

Клиент чужого API. Логика публикации (где искать страницу, чем её метить, что и когда публиковать)
принадлежит вызывающему приложению.

## Тесты

```bash
dotnet test
```

Без сети проверяется всё, что мы формируем и во что разбираем ответ. На живую установку вынесено
то, где заглушка доказывает только намерение: что обложка действительно встала, что кириллица так и
сохранилась, что токен пускает в корзину.

```bash
ALTWAY_TESTS_BOOKSTACK_URL=http://localhost:6875
ALTWAY_TESTS_BOOKSTACK_TOKEN=<id>:<secret>
ALTWAY_TESTS_REQUIRE_STAND=1        # пропуск становится отказом
ALTWAY_TESTS_STAND_ALLOW_WRITE=1    # разрешить пишущие проверки
```

Пишущие проверки закрыты двумя замками сразу: отдельной переменной и сверкой идентификатора
установки с белым списком. Второй замок важнее первого: подмена одной переменной окружения не
сможет увести пишущий прогон на боевой портал.

Созданное несёт отпечаток прогона, пишется в журнал построчно и убирается в обратном порядке,
включая добивание из корзины.
